### 修复「卡在加入网络 + 日志无输出」（连接链路可观测性）
- 用户反馈：点「连接到虚拟局域网」后一直卡在「正在加入网络 633e31d8a2724274……」，日志页从「ZeroTier 节点已启动: ""」之后再无任何输出。
- 根因（四个，都在 ZeroTierService.cs 的 libzt 后端）：
  1. 节点 ID 为空：identity 是异步加载的，`StartAsync` 启动后立刻打日志/返回，IdString 还没出来 → 通知里节点 ID 空。
  2. `WaitUntilAsync` 等 node.Online 20s 超时后**静默继续**，无任何日志 → 节点不在线也继续 Join，之后永远等不到配置。
  3. **日志级别盲区**：`OnZeroTierEvent` 用 `LogDebug`，而 Serilog `MinimumLevel.Information()` → 所有 ZeroTier 事件（上线/离线/ACCESS_DENIED/REQUESTING_CONFIG）全被吞。
  4. `node.Join()` 原生调用在 identity 未加载完时可能**永久阻塞**，JoinNetworkAsync 的日志打在 Join 之后 → 卡住时一条日志都没有，UI 无限停在「正在加入网络」。
  5. 隐藏炸弹：`OrbitMoonAsync` 里 `await Task.Yield()` 后 P/Invoke 仍在 UI 线程同步执行，moon 异常会冻结整个界面。
- 修复（ZeroTierService.cs）：
  - StartAsync：先等 IdString 非空（最多 10s）再打日志；Online 超时后打 Warning + EventRaised「节点尚未上线：可能无法连接 ZeroTier 根服务器」。
  - JoinNetworkAsync：日志移到 Join **之前**（含节点在线状态与节点 ID）；Join 用 `JoinWithTimeoutAsync`（Task.WhenAny + 15s，超时抛 TimeoutException）；等待 30s 超时未就绪打 Warning + EventRaised 把 `status.StatusText` 抛给界面。
  - OnZeroTierEvent：事件码 201/202/210/211/212/213/214/215/216/217 全部映射中文描述 + LogInformation + EventRaised（覆盖：上线/离线/网络不存在/版本过旧/请求配置/配置就绪/拒绝访问(未授权)/就绪v4/v6/网络断开），未知事件保持 Debug。
  - OrbitMoonAsync：P/Invoke 改 `await Task.Run(...)`，不再阻塞 UI 线程。
- 修复（ZeroTierClientBackend.cs，客户端引擎同样的盲区）：
  - StartAsync 成功补 LogInformation；JoinNetworkAsync join 前打日志、30s 超时未拿到虚拟 IP 打 Warning + EventRaised。
  - `GetStatus` 未就绪时新增 `ResolveNetworkStatusText`：解析 `listnetworks -j` 的 `status` 字段（OK/ACCESS_DENIED/REQUESTING_CONFIGURATION/NOT_FOUND/CLIENT_TOO_OLD）翻成中文，不再永远显示「正在加入网络（等待虚拟网卡地址）」。

### 修复客户端引擎「UI 卡死」（sync-over-async 死锁）
- 用户反馈：客户端引擎连接后虚拟网卡出现（IP 10.34.36.111，MSI/服务/join 都成功），但启动器整个 UI 冻结，日志页也点不开。
- **根因（经典 sync-over-async 死锁）**：`ZeroTierClientBackend.JoinNetworkAsync` 被 UI 线程 await（无 ConfigureAwait）→ 拿 `_commandLock` 后**继续在 UI 线程执行** → 轮询里 `ReadVirtualIp` → `ReadListNetworks()` → `RunCommandAsync(...).GetAwaiter().GetResult()` 在 **UI 线程同步阻塞等子进程** → `WaitForExitAsync` 续延 Post 回 UI 线程 → UI 线程被 GetResult 卡住 → 永久死锁。`GetStatus`→`ReadNodeId()` 同样如此。时序：join 已发出（网卡出现）→ 第一次轮询即冻死。
- 叠加问题：RunCommandAsync 无超时（CLI 挂起永久等）；接口同步成员（GetStatus/LocalVirtualIp，Discovery 服务也调）每次同步起子进程。
- **修复（ZeroTierClientBackend.cs 重构）**：
  - 后台刷新循环（`EnsureStatusRefreshRunning`，2s 间隔跑 `listnetworks -j`），结果以**不可变快照**（`NetworkSnapshot` record，Volatile 引用替换）缓存。
  - 所有同步成员（GetStatus/ReadVirtualIp→FindVirtualIp/ReadNodeId→快照.NodeId/LocalVirtualIp/LocalNetworkPrefix/DescribeNetworkStatus）**只读缓存，零阻塞**。
  - JoinNetworkAsync 轮询读快照 + Task.Delay（join 后立即刷一次快照，每轮末尾也刷）；LeaveNetworkAsync leave 后刷新。
  - RunCommandAsync 加 **10s 硬超时**（linked CTS + CancelAfter），超时 Kill(entireProcessTree) 返回失败；先 ReadToEndAsync 再 WaitForExitAsync（防管道缓冲死锁）。
  - Data 层所有 await 加 **ConfigureAwait(false)**（StartAsync/JoinNetworkAsync/OrbitMoonAsync/LeaveNetworkAsync/TryInstallAsync/PingAsync）。
  - PingAsync 改 async 委托 + 先读输出再等退出。
  - Stop() 取消刷新循环。
- 编译通过 0 错误。
- **核心教训：接口同步成员（GetStatus/LocalVirtualIp）绝不能在实现里跑子进程或 sync-over-async；Data 层服务一律 ConfigureAwait(false)；子进程调用必须带超时。**
